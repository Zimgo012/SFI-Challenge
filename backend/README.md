# SFI Challenge Backend

FastAPI backend managed with uv. Requires Python 3.13+ and
[uv](https://docs.astral.sh/uv/getting-started/installation/).

## Local development

Run these commands from the backend directory:

```sh
uv sync --locked
uv run uvicorn main:app --reload
```

The API runs at `http://127.0.0.1:8000`. Open `/docs` for Swagger UI,
`/redoc` for ReDoc, or `/openapi.json` for the OpenAPI document.
`GET /health` returns `{"status": "ok"}` as a basic liveness check.

You can also start the development server with `uv run python main.py`.
To run without automatic reload:

```sh
uv run uvicorn main:app --host 0.0.0.0 --port 8000
```

## Project structure

```text
main.py                         # Application creation and router registration
startup.py                      # Lifespan hook and .env loading
schema/health_schema.py          # Pydantic schemas and model definitions
service/health_service.py        # Business logic
controller/health_controller.py  # FastAPI routes
tests/test_health.py             # HTTP and OpenAPI integration tests
pyproject.toml                   # Project metadata and dependencies
uv.lock                          # Resolved dependency versions
```

Keep each feature's schemas/models in `schema/`, logic in `service/`, and
routes in `controller/`. Use matching names such as `user_schema.py`,
`user_service.py`, and `user_controller.py`. Controllers handle HTTP concerns
and call services; services must not import controllers. Register new routers
with `app.include_router(...)` in `main.py`.

## Startup API hook

Copy `.env.example` to `.env` and set `EXTERNAL_API_URL`:

```dotenv
EXTERNAL_API_URL=https://your-api.example.com/endpoint
```

Implement your async request logic in `service/ingest.py`, inside
`ingest(external_api_url)`. This function is currently a placeholder
and sends no HTTP request. Add your HTTP client as a runtime dependency
(for example, `uv add httpx`) when implementing the call.

`startup.py` loads `.env` beside `main.py` and awaits the service before serving
requests. Existing environment variables take precedence over `.env`. A missing
or blank URL skips the hook. Unhandled service exceptions prevent startup.
The hook runs on every application startup, including reloads and each worker.

The hook uses FastAPI's recommended
[lifespan mechanism](https://fastapi.tiangolo.com/advanced/events/).

## Dispatcher database and migrations

The dispatcher has its own relational database, separate from the external
board API. Local development uses `dispatcher.db` (SQLite) in this directory.
Set `DISPATCHER_DATABASE_URL` in `.env` to override the connection; exported
environment variables take precedence. A blank value uses the local default.
Database files are ignored by Git.

```sh
uv sync --locked
uv run alembic upgrade head       # Create/update the configured database
uv run alembic current            # Show the applied revision
uv run alembic check              # Check models against the migrated schema
```

Models live in separate files under `schema/`: `terminal.py`, `fleet_unit.py`,
`shipment.py`, `evaluation.py`, `dispatch_action.py`, `assignment.py`, and
`historical_shipment.py`. `schema/dispatcher.py` registers all models with the
shared metadata. Migration `0001` creates all seven tables from
`requirements/database-schema.md`, including unique identifiers, foreign keys,
and indexes on foreign keys. A shipment can have only one assignment.

Optional terminal resolutions, evaluation candidates, action evaluations,
pending outcomes, and unavailable pricing/snapshot values are nullable.
Identity and essential lifecycle fields are required. The guide does not
define status enums or scheduling rules, so those remain application logic.
UUIDs are generated by SQLAlchemy on insert; use `Decimal` for numeric values.
Coordinates use `Numeric(10, 7)` and other decimals use `Numeric(18, 6)`.
Store timestamps in UTC; SQLite does not preserve timezone offsets and has
numeric-affinity storage rather than PostgreSQL's exact fixed-point storage.

`service/database.py` provides `get_session` for synchronous FastAPI routes:

```python
from typing import Annotated
from fastapi import Depends
from sqlalchemy.orm import Session
from service.database import get_session

# Add this parameter to a controller function:
# session: Annotated[Session, Depends(get_session)]
```

Services should accept a session and explicitly commit successful writes.
Sessions close automatically and uncommitted work is rolled back. Run migrations
explicitly before starting the API; startup does not create tables or import CSV
data. No board database or external API is modified by these migrations.

After modifying models, generate and review a new migration:

```sh
uv run alembic revision --autogenerate -m "Describe the schema change"
uv run alembic upgrade head
```

To undo the latest migration, use `uv run alembic downgrade -1`.
Downgrading revision `0001` drops all dispatcher tables and their data.
The implementation follows [SQLAlchemy declarative models](https://docs.sqlalchemy.org/en/20/orm/declarative_tables.html)
and [Alembic's migration workflow](https://alembic.sqlalchemy.org/en/latest/tutorial.html).

## Dependencies and tests

```sh
uv add <package>                # Add a runtime dependency
uv add --dev <package>          # Add a development dependency
uv run python -m unittest discover -s tests -v
```

Commit `pyproject.toml` and `uv.lock` together when dependencies change.
uv creates `.venv/` automatically; keep it and local secrets out of Git.
Tests use standard-library `unittest` and FastAPI's HTTPX-backed TestClient.

The layout uses FastAPI's documented
[APIRouter approach](https://fastapi.tiangolo.com/tutorial/bigger-applications/)
and uv's [project workflow](https://docs.astral.sh/uv/guides/projects/).
